# Architecture Decisions Record (DECISIONS.md)

This log records non-obvious technical and architectural decisions made throughout the lifecycle of the Tuck project.

| Date | Decision | Alternatives considered | Why | Reversible? |
|---|---|---|---|---|
| 2026-08-24 | **Remove `.fallbackToDestructiveMigration()` from Room Database setup** | Keep fallback for developer convenience; rely on manual data export before migrations | Strictly violates Tuck Product Law 10 ("Data is sacred; save must never fail, deletion is deliberate"). Destructive migrations risk silent user data loss during app updates. All database evolutions must use explicit, tested SQLite migration scripts. | No (Product Law) |
| 2026-08-24 | **Adopt Room `@Fts4` Virtual Table with Token Prefix Matching (`term*`) for Offline Full-Text Search** | Raw SQLite FTS5 table with triggers; in-memory regex search; separate Lucene index | Room's first-class `@Fts4` entity integration generates robust compile-time verified schema and DAO bindings without requiring custom native SQLite compilation flags across Android API levels. Multi-token prefix matching (`term*`) provides fast sub-10ms query performance on device. | Yes (via Room migration) |
| 2026-08-24 | **Normalize Media Storage into `media_assets` (1:N) rather than single file path columns** | Keep `localFilePath` / `thumbnailPath` on `saved_items`; store JSON array of paths | Enables multi-image posts, carousels, document attachments, and separate thumbnail generation per asset with independent MIME types and SHA-256 hashes. | Yes (via Room migration) |
| 2026-08-24 | **Eliminate abandoned Expo / React Native codebase** | Maintain hybrid build; preserve React Native components as reference | Tuck is built as a pure native Android app (Kotlin, Jetpack Compose, Coroutines/Flow, Room, WorkManager, Hilt). The Expo artifacts were dead weight creating confusion and repo clutter. | Yes (Git history) |
| 2026-08-24 | **Represent Reddit & Social Comment Trees via Materialized Paths in `source_comments`** | Unindexed `commentsJson` string; Adjacency list with recursive CTEs | Materialized path (`0001.0001`) allows instant single-query tree retrieval, depth slicing, and sorting without recursive SQLite joins or unindexed JSON parsing overhead. | Yes (via Room migration) |
| 2026-08-24 | **Topic & Entity Weighted Scoring for Memory Recall over Cloud Vector Embeddings** | Cloud vector search; heavy local on-device neural model | Respects 100% offline local privacy (Product Law 6) and sub-50ms query budget. Combines extracted entity matches (+3.0), tag overlap (+2.0), source domain (+1.5), and keyword tokens. | Yes |
| 2026-08-24 | **Adopt Portable `.tuck` Zip Container for Byte-Identical Vault & Collection Sharing** | Raw database backup; cloud sync API; plaintext JSON dump | A standalone zip containing `manifest.json` + `media/` folder guarantees complete media preservation across Android devices and operating systems without needing cloud servers. | Yes |
| 2026-08-24 | **Quick Settings Tile (`TileService`) for Instant Non-Blocking Capture** | Floating overlay bubble; persistent foreground notification | Native Android Quick Settings Tile allows 1-tap capture from any app or lock screen with zero background battery drain when idle. | Yes |
| 2026-08-24 | **Source Extractor Registry with Platform-Specific Handlers and Offline Fixtures** | Monolithic generic regex crawler; cloud scraper API | Per-platform extractors (Reddit, YouTube, Twitter/X, Generic Web) allow specialized extraction of author, score, and comment trees while remaining 100% offline-testable with verified golden fixtures. | Yes |
| 2026-08-25 | **Cut all AI features from v1: no on-device LLM, no cloud AI, no semantic search** | Ship on-device Gemini Nano / ML Kit GenAI; ship a BYO-cloud-key provider; keep the interface as dead scaffolding | The AI layer was 77 lines of stubs with no working implementation behind it, and shipping a model inflates the APK and fragments by device support. Cutting it makes v1 a fast local archive whose value is capture plus retrieval. Consequence: keyword search is now the *only* retrieval path, so search ranking quality becomes the top product priority. `derived_summaries` and `derived_points` tables are left in place rather than migrated away, so the feature can return without a schema change. | Yes |
| 2026-08-25 | **Defer cloud backup, sync, accounts and shared collections** | Build sync now alongside local storage | Local vault export/import and the `.tuck` collection pack already work and are the right foundation; a future cloud layer sits on top of them rather than replacing them. Local-first stays true with no account required. | Yes |
| 2026-08-25 | **Own the FTS4 table directly and rank with `matchinfo`, after confirming Android has no `fts5`** | Raw FTS5 virtual table with BM25; bundle SQLite via `androidx.sqlite:sqlite-bundled`; keep Room `@Fts4` unranked | An FTS5 table was implemented and failed on device with `no such module: fts5` - Android's bundled SQLite omits it, which is why Room only ever offered `@Fts4`. Ranking now comes from FTS4's `matchinfo('pcnalx')`, scored in Kotlin with per-column weights (title 8, tags 5, entities 4, body 3, OCR 2) and length damping. Fixes relevance sort, which previously returned rowid order, i.e. oldest first. Bundling SQLite would restore BM25 but costs APK size and a Room 2.7+ driver migration. | Yes |
| 2026-08-25 | **Strip `-` from search queries** | Preserve hyphens; escape them; quote every token | In FTS4 query syntax a leading hyphen is the NOT operator, so "nike-air" parsed as `nike AND NOT air` and excluded the rows it should have matched. Quoting each token instead was tried and rejected: FTS4 applies the `*` prefix operator only to barewords, so quoting silently broke all prefix search. | Yes |
| 2026-08-26 | **Emit deterministic `PERSON` entities from structured source metadata with platform-qualified handles** | NER model on body text; ML Kit entity extraction; un-prefixed raw display names | ML Kit does not extract person names without a model, and NLP name detection on prose produces false-positive merges. Structured source metadata (Reddit `authorHandle`, YouTube channel, X handle, Web article author) provides 100% deterministic, exact identities. Platform-prefixing (`reddit:someone`, `youtube:channel`, `twitter:handle`, `web:author`) prevents cross-platform collision while enabling exact matching and +3.0 RelatedItems scoring. Recorded with `producer = "source-metadata"`. | Yes |
| 2026-08-26 | **Visual Redesign R0 Architecture: 1 Signature Palette, Curated 14-Color Saturated Collection Tiles, Plus Jakarta Sans, 4-Tab IA** | 10 separate flavor designs; dynamic wallpaper tinting; free custom color picking; merging Inbox into Collections | Concentrating design polish on 1 Signature warm-paper palette (Linen light / Obsidian dark) with 14 WCAG-contrast-certified saturated collection tile colors guarantees high-craft editorial aesthetic without visual dilution. Preserves 4-tab IA and offline privacy laws. | Yes |
| 2026-08-26 | **Rebuild Theme System with OKLCH Perceptual Multi-Hue Families across 8 Coordinated Slots** | HSL/HSV uniform angle spacing; raw sRGB hex palettes; per-theme manual tweaking | OKLCH provides perceptual uniformity where lightness ($L$) and chroma ($C$) directly match human vision. Holding lightness constant across coordinated slots guarantees mathematical accessibility ($\ge 4.5:1$ text contrast, $\ge 3:1$ tile separation). All 5 theme families (**Linen**, **Noir**, **Forest**, **Cobalt**, **Plum**) in Light and Dark are generated from 8 calibrated slots (`TERRACOTTA`, `AMBER`, `MUSTARD`, `SAGE`, `TEAL`, `DENIM`, `PLUM`, `ROSE`) with gamut-clamping and verified under Viénot 1999 CVD simulation (Deuteranopia, Protanopia, Tritanopia). | Yes |
